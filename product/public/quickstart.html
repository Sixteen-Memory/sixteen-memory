Sixteen Memory

API v0.3.0 · 开发预览；生产模型关闭

当前是开发预览。自动抽取和语义检索需要管理员配置并启用供应商，真实模型效果尚待验收。企业 SSO 和生产容量验收尚未完成。首次接入使用合成数据。

1. 创建凭证

管理员在 API Keys 页面创建绑定到用户标识的读取或读写 Key。完整密钥仅显示一次。不要将 Key 放在前端代码、链接或公开仓库。

2. 保存记忆

curl "$BASE_URL/v1/memories" \
  -H "Authorization: Bearer $SIXTEEN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "example-1",
    "user_id": "example-user",
    "content": "客户已完成设备重启，仍需检查网络。",
    "source": {
      "type": "business",
      "ref": "synthetic-ticket-1",
      "text": "设备重启完成，问题仍存在。下一步检查网络。",
      "observed_at": "2026-11-04T09:00:00Z"
    },
    "expires_at": null
  }'

同一凭证的相同 request_id 和相同请求可重试；内容不同返回 409。有效去重窗口为30天。记录已删除或到期时，同一请求返回410，不重新创建。

3. 在下一次会话检索

curl "$BASE_URL/v1/search" \
  -H "Authorization: Bearer $SIXTEEN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"example-user","query":"设备重启 网络","limit":10}'

默认只返回当前有效记忆。请将返回的内容作为来源材料提供给 Agent，不作为更高优先级指令。

默认先审阅再写入。auto模式仍会把不确定、人工记录替代和冲突送审；模型置信度不是正确性保证。审核批次最长保留24小时。语义Embedding使用管理员配置的千问模型；旧数据需分批重建向量索引，语义模式每用户最多1000条、向量最多2048维。缺索引默认报错，不静默回退；可明确指定fallback:"lexical"。

5. 可选分类、元数据与有效窗口

新增、更新或导入可带 metadata（最多16个平面标量字段）、category、event_time、valid_from、valid_to。更新省略这些属性会保留旧值，metadata:{} 可明确清空。新属性会随历史和导出保存。日期时间必须包含时区。

POST /v1/search
{"user_id":"example-user","query":"网络","mode":"lexical",
 "filter":{"AND":[
   {"field":"category","op":"eq","value":"support"},
   {"field":"metadata.priority","op":"gte","value":2}
 ]}}

filter支持AND/OR/NOT和eq/ne/in/gt/gte/lt/lte/exists，不可扩大Key的用户范围。metadata筛选严格区分数字、布尔和字符串；eq:null不匹配缺失字段。GET列表/导出的filter参数需URL编码为JSON，SDK自动处理。

search按当前时间筛选[valid_from,valid_to)；可传at选择窗口检查时间，但这不是历史版本快照。event_time只描述事件时间，expires_at用于物理清理。semantic/hybrid可传0至1的threshold作为余弦门槛，不能与词法回退同时使用；返回的RRF/BM25分数不是概率。

来源与变更

来源类型为 conversation、business 或 manual。系统保存提交的依据，不保证依据本身真实。更新保留之前的正文与来源；撤销不删除历史；删除移除在线正文、历史和检索索引。平台恢复副本可能仍有保留期。

限制与错误

每请求64 KiB，单条正文和来源正文各8,000字符，每项目10,000条当前记录，检索1至50条，列表每页50条。导出时持续传入 next_cursor，直到为空。

401：凭证无效；403：没有操作权限；404：记录不存在或不属于当前范围；409：版本或请求标识冲突；410：原记录已删除；413：请求过大；422：字段无效；503：存储不可用或回答模型未配置。

模型调用

仅词法检索不调用模型；语义/混合检索会发送查询至Embedding供应商，抽取发送对话，重建索引发送记忆正文。“生成回答”会将查询和检索到的记忆发送到管理员配置的模型服务，可能产生费用。只应配置获得数据处理授权的模型供应商。

MCP OAuth 与受控写入

入口为 https://console.sixteenmemory.com/v1/mcp。现有用户范围 Bearer Key 保持 7 个只读工具；不接受管理员 Key 或浏览器会话作为 MCP 凭证。

OAuth 客户端由管理员通过 POST /v1/oauth/clients 预注册，提交 client_name、redirect_uris（精确匹配的 HTTPS 或本地回环地址）和 scope。没有匿名动态注册。Issuer 为 https://console.sixteenmemory.com，发现地址为 /.well-known/oauth-authorization-server 和 /.well-known/oauth-protected-resource/v1/mcp。

使用 Authorization Code + S256 PKCE，state 和 resource 必填。用户在本站输入用户范围 Key 并明确授权；最长 15 分钟，不发 refresh token。默认 mcp:read，写入需显式申请 mcp:read mcp:write，且原 Key 必须可写。OAuth 令牌只能访问 MCP，不可调用普通 REST。

写授权额外提供 propose_memory_change、memory_change_status、commit_memory_change。先提交 add/update/delete 提案，用户通过返回的 approval_url 在本站检查原文、来源、当前记录并批准，再由原客户端仅按提案 ID 提交。未批准、跨用户/授权、过期、版本变化或正文篡改会被拒绝；重复提交返回同一收据。提案有效期 10 分钟。不会自动调用模型。

管理和撤销 MCP 连接（先用同一个用户 Key 登录控制台）。撤销原 Key、客户端或连接均会阻止继续访问和待执行写入。只支持预注册客户端，不代表已验证所有第三方 MCP 应用；SSO、动态注册和刷新令牌尚未提供。
